# Transición profesional a Full Stack Developer

## Objetivo

Esta documentación organiza y da seguimiento a la transición profesional hacia el posicionamiento de **Full Stack Developer con fortaleza en Frontend**. Su propósito es mantener una narrativa clara, verificable y consistente en el Portfolio, el CV, LinkedIn, GitHub y el resto de la presencia profesional.

La transición no implica abandonar la especialización en interfaces ni presentarse como especialista en todas las áreas del desarrollo. Busca comunicar con precisión una capacidad de trabajo integral: construir experiencias de usuario, desarrollar funcionalidades de backend, modelar y consultar datos, integrar servicios y aplicar controles de acceso.

## Posicionamiento elegido

El posicionamiento principal es **Full Stack Developer**.

La fortaleza diferencial está en Frontend, con experiencia principal en:

- React
- Next.js
- TypeScript
- JavaScript
- Tailwind CSS

El alcance Full Stack se sostiene con experiencia en:

- Node.js
- Supabase
- PostgreSQL
- SQL
- REST APIs
- Authentication
- Authorization
- Row Level Security (RLS)

El trabajo se complementa con Git, GitHub, GitHub Actions, Vercel y Figma.

## Qué significa “Full Stack con fortaleza en Frontend”

Significa poder participar en el desarrollo completo de un producto, desde su interfaz y experiencia de usuario hasta la persistencia de datos, la autenticación, la autorización y las integraciones necesarias.

Frontend continúa siendo la principal fortaleza técnica y el área de mayor profundidad. El posicionamiento Full Stack se apoya en evidencia concreta de proyectos que incluyen backend, bases de datos, APIs y seguridad. No supone presentarse como Backend Developer puro ni atribuir experiencia no demostrada en infraestructura, microservicios o arquitectura distribuida.

## Evidencia principal

Los proyectos que respaldan esta transición son:

1. **Balance App:** aplicación Full Stack para finanzas compartidas, con autenticación, hogares, invitaciones, gastos, servicios, PostgreSQL, SQL, RPCs, autorización y RLS.
2. **Jujuy Conecta:** diario digital y CMS con panel administrativo, Supabase, gestión dinámica de contenido, SEO, scraping y automatizaciones con Python y GitHub Actions.
3. **Colegio de Antropólogos de Jujuy:** sistema institucional con autenticación, administración, gestión dinámica de datos y consulta pública de profesionales.
4. **Dealer Platform / Autopoint:** plataforma multi-tenant en desarrollo para concesionarias, con autenticación, onboarding, dealerships, perfiles, staff, permisos mediante RLS e inventario de vehículos.
5. **Club Deportivo Luján:** proyecto institucional real que demuestra trabajo con clientes, producto, diseño, comunicación y entrega.

## Uso de esta documentación

Este directorio funciona como fuente interna de coordinación para la transición:

- `README.md` define el objetivo, el alcance y la narrativa profesional.
- `CHECKLIST.md` registra avances, pendientes y prioridades.
- `DECISIONS.md` conserva las decisiones que orientan el posicionamiento y evita contradicciones entre canales.

La documentación debe actualizarse cuando cambie el estado de una tarea o se tome una decisión relevante. Toda afirmación profesional debe mantenerse alineada con experiencia y evidencia reales.
